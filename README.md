# Handoff: Bespoke Healthcare marketing site

## Overview
Marketing site for **Bespoke Healthcare**: a membership that pairs an AI assistant ("Shifu") with licensed human experts (registered dietitians, certified exercise coaches) under one plan. Sixteen pages: home, two discipline pages (Nutrition, Exercise), a Coverage page (topics + team profiles), and twelve goal landing pages. Plans: Starter $0 / Core $49 / Plus $79 per month. A written check-in costs 1 consult; a 10-minute live video call costs 2.

Also bundled: `Logo Ideas.dc.html`, an exploratory logo brainstorm (12 directions, none approved). The site ships with a plain text wordmark; do not build a logo from that file.

The nav wordmark on every page is **Shifu Health** (the company; Supamill Inc, DBA Shifu Health). "Bespoke Healthcare" remains the home-page H1 and the product name; the discipline pages keep their "Bespoke Nutrition" / "Bespoke Exercise" wordmarks with a "by Shifu Health →" link home.

### Care team roster
Every person shown on the site is a real member of the live shifu.health care team. The roster lives in `shifu-team.js` (`window.SHIFU_SITE_TEAM`; the same data as `team.json`) and is loaded by every page before `support.js`. It is generated by `node gen-team.mjs` from the live site's `team-data.js` plus `team-overlay.json` (discipline, card credential and license lines, short bio, Coverage topics). Photos are copied into `assets/team/`. Fields per person: `id` (slug), `kind` (`n` nutrition, `e` exercise, `a` clinical advisor: not bookable, `f` founding team, `i` investor), `name`, `cred`, `cardCred`, `role`, `states`, `bio`, `specs` (must match Coverage topic labels), `img` (self-hosted), `liveImg`, `profileUrl` (`https://shifu.health/team/<id>/`), `background[]`, `education[]`, `credentials[]`, `links{linkedin,business}`, `dietitian`, `licensedStates[]`, `advisorRole`, `disclaimer`. Do not hand-edit the roster: change `team-overlay.json` or the live site and regenerate. To add or swap someone, edit the overlay (the id must exist in the live roster, or carry a full `person` record as the founders do, since they are on shifu.health/about rather than in the care-team data) and rerun the script. Coverage lists kinds n/e/a only; the Manifesto page shows everyone.

Everywhere a person appears links to `Coverage.dc.html?profile=<id>#team`, which opens that person's full profile in the Coverage page's modal. Team cards are uniform: square photo (radius 12, 1px line border, surface bg), name, one-line credential, modelled on the shifu.health team carousel.

## About the design files
Everything here is a **design reference written in HTML**: prototypes that show the intended look and behavior, not production code to ship. The job is to **recreate these designs in a real codebase**. No codebase exists yet (the client's `New Website` folder is empty), so pick the stack. A static-first framework (Next.js or Astro) with plain CSS or Tailwind fits: 16 mostly static pages, small islands of client-side interactivity, no backend beyond an optional lead-capture endpoint.

### How to read a `.dc.html` file
Each file is one self-contained page. To view it, serve this folder over HTTP (`npx serve .`) and open the file; `file://` will not work. Inside `<x-dc>…</x-dc>` is ordinary HTML with a few conventions:

- All styling is inline `style="…"`. `style-hover="…"` is the `:hover` state. The only classes are `nav-link` / `nav-wordmark` on the nav and the home-page strip classes; `mobile.css` (linked from every helmet) holds the phone rules, matching inline-style text with `[style*=…]` selectors: nav links hide under 900px, gutters drop to 20px, two-column grids stack and cards go single-column under 720px, face grids go three across under 480px.
- `{{ name }}` is a value supplied by the `class Component` in the `<script data-dc-script>` at the bottom of the file. Its `renderVals()` returns every `{{ }}` value: text, computed style objects (camelCase CSS, bare numbers = px) and click handlers. Read it for all data (team members, FAQ, day timeline, plan calculator) and interaction logic.
- `<sc-for list="{{ items }}" as="x">` is `items.map(x => …)`; `<sc-if value="{{ flag }}">` is a conditional; `$index` is the loop index.
- `<image-slot>` is an image placeholder the client has not filled yet (see Assets). Render a real `<img>` there.
- `<helmet>` holds `<head>` content: Google Fonts link, favicon, body reset.
- Ignore `support.js`, `image-slot.js`, `hint-*` attributes and `data-screen-label`: prototype plumbing.
- `data-props` on the script tag lists site-level config: `smsNumber`, `appStoreUrl`, `leadFormAction`.

## Interactions and behavior
- **Start / CTA links**: `sms:{smsNumber}?&body={URL-encoded message}` opens the SMS app with a prefilled text. Default "Hi Shifu, I'd like to get started."; topic and goal variants as above. `smsNumber` and `appStoreUrl` are site config (placeholders `+10000000000`, `https://apps.apple.com/`).
- **Lead capture** (discipline heroes): require ≥ 10 digits; if `leadFormAction` is set, POST JSON `{ phone, goal, source: "website-hero" }`; then show the sent state.
- **Auto-rotating showcases**: home disciplines every 4.5s (stops after a click) · coach mode tabs every 7s (stops after a click) · day timeline every 4.2s (10s pause after a click) · quotes every 5.2s · live-call countdown ticks every second from 10:00 and wraps.
- **Hover**: primary → orange fill · secondary → ink fill · chips → ink (or orange) fill · goal rows → ink border · nav links → ink · dark-footer links → white.
- **Anchors** scroll smoothly.
- **Responsive**: all grids use `auto-fit` and collapse naturally; type scales with `clamp()`. Discipline pages hide nav links below 1000px and show the sticky bottom bar below 720px. Nothing else is breakpoint-specific.
